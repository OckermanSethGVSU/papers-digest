# Vector Search Digest — 2026-11-20

## Highlights

- **[Variants of Beam Search for DiskANN](http://arxiv.org/abs/2611.26609)** — It unifies the alpha-reachable and adaptive-beam-search guarantees into one approximation bound, then turns that analysis into a learned per-query beam predictor that cuts SSD-resident DiskANN latency by up to 29.6% at matched recall on 100M-point datasets.
- **[Standardized Tolerance for Adaptive Reuse and Repair: A Method for HNSW Migration Under Embedding Model Change Scenarios](http://arxiv.org/abs/2611.25416)** — It tackles a real operational problem, re-indexing after an embedding model upgrade, by reusing old HNSW edges, with a median 16.7x build speedup at about 1 pp recall loss across 240 model transitions.

## Graph ANN: search, maintenance, privacy

### [Variants of Beam Search for DiskANN](http://arxiv.org/abs/2611.26609)
_Viraj Agrawal, Kirankumar Shiragur | 2026-11-19 | arXiv (cs.IR) | ⭐⭐⭐_

The paper proves that adaptive beam search with relaxation gamma on alpha-reachable graphs achieves an (α+1)/(α(γ+1)−1) approximation for any metric, with a tighter bound on sorted alpha-reachable graphs under L2. Building on that analysis, it trains a beam predictor that minimizes mean distance computations subject to a target recall. On three 100M-point benchmarks the predictor cuts SSD query latency by up to 29.6% versus classical beam search and is usually a few percent faster than ABS, with larger gains at k=500.

**Vector search angle:** Replacing a fixed L / beam-width stopping rule with a learned per-query termination predictor is a drop-in change to DiskANN-style search loops, and it saves the most I/O at large k and high recall.

### [Standardized Tolerance for Adaptive Reuse and Repair: A Method for HNSW Migration Under Embedding Model Change Scenarios](http://arxiv.org/abs/2611.25416)
_Hengzhao Ma, Chenyang Zhu, Bin Wang et al. | 2026-11-19 | arXiv (cs.DB) | ⭐⭐⭐_

STARR migrates an HNSW index after an embedding model change. It compares standardized edge lengths of the same neighbor lists in the old and new spaces, keeps edges within a correlation-derived tolerance, and repairs the affected vertices by searching the partially migrated graph. A final repair pass provably guarantees base-layer reachability under degree limits. On 1M-object datasets it gets 5–45x construction speedup over a fresh build, with recall usually within 1 pp.

**Vector search angle:** Vector DBs can offer cheap model-upgrade re-indexing by seeding the new graph from old adjacency and repairing only distorted regions instead of rebuilding from scratch.

### [Efficient Privacy-Preserving High-Dimensional Approximate Nearest Neighbor Search](http://arxiv.org/abs/2611.25374)
_Lyu Xu, Guozhong Li, Qichen Wang | 2026-11-19 | arXiv (cs.DS) | ⭐⭐⭐_

ObliSC targets asymmetric private ANN search, where the database is public but queries must stay hidden from an untrusted server, including their access patterns. It combines a fully oblivious search base with parallel candidate retrieval and refinement that preserve obliviousness. On six standard ANN benchmarks it is competitive in efficiency and quality with a lighter index than other private-ANN approaches.

**Vector search angle:** This is relevant for hosted or serverless vector search offerings that need query confidentiality: access-pattern leakage, not just encryption, is the threat model, and it constrains which index traversal patterns are viable.

## In-memory / in-flash similarity search hardware

### [CAIMS: Scalable Cross-Array In-Memory Search](http://arxiv.org/abs/2611.25141)
_Yi-Chun Liao, Liu Liu, Ruiyang Qin et al. | 2026-11-18 | arXiv (cs.LG) | ⭐⭐_

CAIMS scales content-addressable-memory top-k similarity search across many arrays. Each array only emits binary threshold matches, so CAIMS turns those local results into globally comparable coarse scores using thresholds chosen offline and online. Hierarchical reduction then merges results to a global top-k. On a 3D NAND model running RAG retrieval it reports up to 22x throughput and 427x energy efficiency over a server CPU.

**Vector search angle:** The core problem is merging local candidates that lack comparable scores into a global top-k, the same issue sharded or partitioned vector search faces, and threshold-calibrated coarse scoring is a transferable idea.

### [RE-CAM: Readout-Enhanced Content-Addressable Memory for Quantitative Similarity Search](http://arxiv.org/abs/2611.25326)
_Yi-Chun Liao, Dongyoung Lee, Jiazheng Chen et al. | 2026-11-19 | arXiv (cs.LG) | ⭐⭐_

RE-CAM extracts quantitative similarity, not just binary match, from a CAM search. It senses the time-varying match-line voltage multiple times and jointly optimizes sensing timestamp, reference voltage and decoding parameters. It approximates linear and nonlinear functions with lower error and reports 8x search throughput with 47% less energy than a uniform ADC baseline.

**Vector search angle:** This makes CAM-based accelerators produce graded distances usable for top-k ranking rather than threshold filtering, which matters if hardware Hamming or binary-code search is part of your serving roadmap.

### [FlashX: Scaling Robotic Experience Reuse for Embodied Agents with CBA-Based NAND Flash](http://arxiv.org/abs/2611.25580)
_Yuseon Choi, Sanghyeon Park, Eunjong Lee et al. | 2026-11-19 | arXiv (cs.AR) | ⭐⭐_

FlashX is a NAND flash architecture with CMOS bonded directly to the array (CBA) that performs key search inside flash for retrieving robot experiences. Search keys live in pSLC with compute-in-flash engines, while dense latents stay in TLC. Proprioception-aware clustering prunes the search and supports incremental inserts without global reclustering. It reports 2.57x search throughput over prior NAND search, a further 9.7x reduction from clustering, and 1.3–4x end-to-end speedup over SSD-based retrieval.

**Vector search angle:** It is a concrete data point for computational-storage ANN: keep keys and codes in fast media for in-situ scanning, keep full vectors in dense media, and use IVF-like clustering that tolerates incremental inserts.

## Compressed, tiered caches in LLM serving (transferable to vector serving)

### [Twindex: Index Cache Offloading with Coarse-to-Fine Selection for Long-Context Sparse-Attention Serving](http://arxiv.org/abs/2611.25078)
_Yuxuan Xia, Jiakun Fan, Han Meng et al. | 2026-11-18 | arXiv (cs.DC) | ⭐⭐_

Sparse-attention models score every past token with an indexer cache, and once the main KV is offloaded that cache becomes the HBM bottleneck. Twindex keeps a compressed copy in HBM (a shared component plus learned compressed residuals) to select a larger candidate set, then reranks candidates against the full-precision rows in host memory. It fits 1.6–3x more requests at 1M tokens with at most 3.1% score loss.

**Vector search angle:** This is exactly the compressed-in-fast-memory candidate generation plus full-precision rerank from a slower tier pattern used in DiskANN/PQ, now applied to attention top-k, and its learned shared-plus-residual compression is worth comparing against PQ/RaBitQ.

### [TripleKV: Predict, Prefetch, Protect -- KV Cache Management for AI Agents](http://arxiv.org/abs/2611.25112)
_Shashwat Jaiswal, Chloe Alverti, Mengmei Ye et al. | 2026-11-18 | arXiv (cs.DC) | ⭐_

TripleKV manages agent KV caches across GPU, DRAM and SSD tiers. It predicts tool-call completion times to prefetch blocks from SSD into DRAM, deduplicates GPU-resident blocks out of DRAM, and uses an SSD-backed victim cache. Critical-path SSD reads drop from 45–76% to under 10% of requests, and P95 TTFT falls by up to 49%.

**Vector search angle:** Its timing-predicted prefetch into DRAM and exclusive-tier victim caching are applicable to tenant-level warmup of tiered or disk-resident vector indexes in multi-tenant serving.

### [AscMLA: Unlocking FP4 Efficiency for Long-Context MLA Decoding through Asymmetric Scaling](http://arxiv.org/abs/2611.26106)
_Zechun Zhou, Zhiyong Zheng, Xiaomin Zhang et al. | 2026-11-19 | arXiv (cs.DC) | ⭐_

AscMLA stores the shared latent KV of multi-head latent attention as a single FP4 payload. Asymmetric per-use scales and pipelined scale delivery reconcile the different K and V scaling needs without dequantization or duplicate encodings. It uses 38% less cache memory than FP8, with 1.26–1.35x kernel speedups.

**Vector search angle:** It is a reference for block-scaled FP4 storage and computing directly on the 4-bit payload, relevant if you are considering FP4/NVFP4 vector codes for GPU distance kernels.

### [HiSA: Sparsifying the Hidden Dimension of RoPE Attention in LLMs](http://arxiv.org/abs/2611.26363)
_Ambroise Borbely, Mathieu Salzmann, Olivier Verscheure | 2026-11-19 | arXiv (cs.LG) | ⭐_

HiSA computes only a partial query-key dot product, about a third of the dimensions, chosen by a static rule from token positions and the RoPE structure. LLMs trained from scratch with HiSA match or beat dense attention. FlashAttention-3 kernels give faster decoding and a smaller memory footprint.

**Vector search angle:** It is weak evidence that learned embeddings can be trained to tolerate structured partial inner products, which is the same premise behind dimension-subset early termination and Matryoshka-style truncated distance computation.

## Quantized IDs, retrieval modeling, clustering theory

### [LQ-Rec: Late Quantization for Sequential Recommendation](http://arxiv.org/abs/2611.25256)
_Satoshi Koide, Yueqi Wang, Julian McAuley | 2026-11-18 | arXiv (cs.IR) | ⭐⭐_

LQ-Rec keeps the encoder and scoring in continuous space and quantizes only the item side, using an end-to-end-trained residual quantizer whose codes serve as semantic IDs. It proves an additive error decomposition and a pairwise ordering bound on quantization-induced ranking loss. Ranking quality improves monotonically with code length, and one model supports anytime compression.

**Vector search angle:** Asymmetric scoring with a continuous query against residual-quantized items, plus a provable ranking-drop bound and prefix-truncatable codes, maps directly onto ADC with RQ/additive quantizers and progressive-precision reranking.

### [CACO: Coverage-Aware Coordinated Optimization for Continuous Generative Retrieval](http://arxiv.org/abs/2611.25738)
_Pan Zhang, Nan Zhuang, Yongkang Zhang et al. | 2026-11-19 | arXiv (cs.IR) | ⭐_

CACO post-trains flow-matching and diffusion retrievers so that their multiple sampled queries cover complementary ANN neighborhoods instead of overlapping ones. It uses a label-free coverage objective and a counterfactual gradient estimator that works through non-differentiable top-K search. Recall@100/400 improves by up to 24% and inter-query overlap drops 53–65%, at 0.5–3% extra latency.

**Vector search angle:** Its result that multi-query ANN budgets are wasted on overlapping neighborhoods is a useful signal for multi-vector and multi-query search APIs (dedup-aware probing, diversified query fan-out).

### [Exploring Semantic Table Search in Data Lakes](http://arxiv.org/abs/2611.25691)
_Martin Pekár Christensen, Matteo Lissandrini, Katja Hose | 2026-11-19 | arXiv (cs.IR) | ⭐_

Thetis++ combines keyword and entity-embedding semantic table search, comparing rank-fusion methods (including TOPSIS) and learning-to-rank. For scalable semantic prefiltering it compares LSH with HNSW and finds HNSW 4.7x faster with table quality retained.

**Vector search angle:** It is a modest applied data point that HNSW beats LSH as a candidate prefilter in entity-embedding table discovery, and that hybrid fusion choice matters.

### [Embeddings vs. Grep: Rethinking the Dense Advantage in Code Search](https://huggingface.co/papers/2611.20455)
_Siqiao Xue, Ziyin Zhang, Zihan Liao et al. | 2026-11-16 | HuggingFace | ⭐_

Repo-Premium is a realistic repository-level code search benchmark built from PRs across six languages. On it, much of the reported dense-over-BM25 advantage comes from evaluation choices and from queries that lack the code's rare identifiers. Expanding queries with LLM-written identifiers lets BM25 match dense retrieval, and the authors recommend hybrid fusion.

**Vector search angle:** It strengthens the case for first-class hybrid (dense plus lexical) retrieval in vector engines for code workloads, and warns against benchmarking dense indexes against a handicapped BM25.

### [Subexponential Algorithms for Continuous Euclidean $k$-Means in Subpolylogarithmic Dimension](http://arxiv.org/abs/2611.25305)
_Junqi Tan | 2026-11-19 | arXiv (cs.DS) | ⭐_

The paper gives a deterministic, polynomial-space exact algorithm for continuous Euclidean k-means running in 2^{o(n)} time for arbitrary k when d=(log n)^{o(1)}. This answers an open question about beating 2^n time for this regime.

**Vector search angle:** It is purely theoretical and limited to very low dimension, so it has no practical impact on IVF/PQ codebook training; it is included only as k-means complexity background.
